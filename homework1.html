Part I: Elliptic Curve Scalar Multiplication (Toy Model)

In Ethereum and Bitcoin, public keys are derived from private keys via scalar multiplication on the secp256k1 curve ($y^2 = x^3 + 7 \pmod p$). Because the discrete logarithm problem on elliptic curves (ECDLP) is computationally intractable, calculating $Q = kG$ from $k$ is fast, but recovering $k$ from $Q$ is virtually impossible.

We demonstrate this one-way function principle using a simplified toy curve over the finite field $\mathbb{F}_{17}$:

$$y^2 \equiv x^3 + 7 \pmod{17}$$
  • Base Point ($G$): $(1, 5)$
  • Private Key ($k$): $6$
  • Toy Public Key ($Q$): $Q = kG = 6G$

2. Elliptic Curve Arithmetic over $\mathbb{F}_p$

To find the next point when adding $P = (x_1, y_1)$ and $R = (x_2, y_2)$ on $y^2 = x^3 + a x + b \pmod p$:

POINT ADDITION ($P \neq R$)

$$\text{Slope } s \equiv \frac{y_2 - y_1}{x_2 - x_1} \pmod p$$

Used when adding two different points

POINT DOUBLING ($P = R$)

$$\text{Slope } s \equiv \frac{3x_1^2 + a}{2y_1} \pmod p$$

Used when adding a point to itself

NEXT POINT $(x_3, y_3)$

$$x_3 \equiv s^2 - x_1 - x_2 \pmod p$$ $$y_3 \equiv s(x_1 - x_3) - y_1 \pmod p$$

These formulas apply once the slope $s$ is found. Note that $p = 17$ and $a = 0$ for our curve.

Part II: Ethereum Wallet Cryptographic Pipeline

Practical wallets (e.g., MetaMask, Rabby, Exodus) derive addresses via a multi-stage pipeline combining derivation, asymmetric cryptography, hashing, and checksums:

Mnemonic Words → [BIP-39] → Seed (512 bits)
→ [BIP-32 / BIP-44] → Private Key ($k$)
→ [secp256k1] → Public Key ($Q = kG$)
→ [Keccak-256] → Raw Address (Last 20 Bytes)
→ [EIP-55] → Checksummed Address

Roles of Key Standards & Cryptographic Primitives

  • BIP-39: Converts entropy into a readable 12/24-word mnemonic phrase and derives a binary seed using PBKDF2.
  • BIP-32 / BIP-44: Hierarchical Deterministic (HD) key derivation tree. Ethereum standard path: m / 44' / 60' / 0' / 0 / index.
  • secp256k1: Elliptic curve used for deriving public key $Q = kG$ and signing transactions.
  • Keccak-256: Cryptographic hash function used to hash the uncompressed public key (64 bytes). The address takes the last 20 bytes.
  • EIP-55: Encodes mixed-case checksum formatting based on the Keccak-256 hash of the address string to prevent typing errors.

5. Conceptual Distinctions & Timeline Context

Key Derivation vs Generation

Generation relies on true random entropy. Derivation deterministically computes child keys from a master secret via pseudo-random functions.

Public-Key Cryptography

Asymmetric math (secp256k1) enabling digital signatures: private keys sign transactions, public keys verify them without revealing secrets.

Hashing vs Checksum

Hashing (Keccak-256) is a one-way transformation mapping data to fixed bitstrings. Checksums (EIP-55) append redundancy to detect input errors.

Chronological Context & Hash Differences

  1. RSA (1977): First widely used asymmetric cryptosystem based on integer factorization.
  2. SHA-2 / SHA-512 (2001): NIST standard hash functions built on Merkle–Damgård structure.
  3. BIP-32 (2012): Introduced Bitcoin HD wallets to manage tree-structured key hierarchies.
  4. BIP-39 (2013): Standardized human-readable mnemonic recovery phrases.
  5. BIP-44 (2014): Multi-account HD wallet path conventions for multiple cryptocurrencies.
  6. SHA-3 (2015): NIST standard based on the Keccak sponge construction.
  7. EIP-55 (2016): Ethereum proposal for mixed-case checksum address formatting.

SHA-2 vs Keccak-256 vs SHA3-256

SHA-2 uses Merkle–Damgård construction; Keccak uses a sponge construction. Ethereum adopted Keccak-256 prior to official NIST SHA-3 standardization. Official SHA3-256 uses a different domain separation padding (0x06) compared to Ethereum's original Keccak-256 (0x01), yielding different hash values for identical inputs.
